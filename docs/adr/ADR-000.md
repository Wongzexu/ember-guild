# ADR-000: 模板与编号规则（Template & Numbering）

> 日期：YYYY-MM-DD
> 状态：模板（Template）
> 关联：—

## 这是"模板 + 编号规则"文档，不是真实决策

`ADR-000` 是**空白模板**，供新建 ADR 时复制使用。真实决策从 `ADR-001` 开始顺序编号，**不要**使用 ADR-000。

### 编号规则

- 新决策取当前最大编号 +1（当前最大为 `ADR-000`，故下一篇是 `ADR-001`）。
- ADR 按写定的顺序追加，**永不重排**；即使某个决策被后续推翻，也保留其编号并在该 ADR 的状态/关联字段注明修订关系。
- 每个 ADR 一个文件：`docs/adr/ADR-NNN.md`。
- 与现有 ADR 相关时，在「关联」字段用 `ADR-NNN` 交叉引用。

### 状态取值

- `proposed` 提议中
- `accepted` 已接受（可追加「评审记录」，见 `grill-mycode` skill）
- `deprecated` 已被替代（在「关联」注明替代者）
- `superseded-by` 被某 ADR 推翻（写法：`状态：superseded（被 ADR-NNN 替代）`）

## 供参考：一段游戏项目示例（改自已完成的 ADR 风格）

```markdown
# ADR-001: 核心玩法采用回合制而非实时

> 日期：2026-08-26
> 状态：accepted

## 一、背景
GDD 中核心循环含"行动点分配→结算→敌人阶段"。初稿曾考虑实时
（RTS-like）以降低节奏门槛，但暴露了网络同步与 AI 决策复杂度过高、
单机离线校验困难的问题。

## 二、决策
采用**回合制**（turn-based），行动点制，玩家与敌人轮流结算。

## 三、后果
正面：可预测、易做存档/回放/离线、AI 可离线跑通、测试友好。
代价：动作节奏较慢；后续若想引入实时玩法，需独立模块，勿在回合框架上打补丁。

## 四、排除事项
- 不在本次评审引入实时战斗或混合时序；
- 不预埋在线 PvP 同步层。

## 五、实施与验证
1. 用 `grilling`/`grill-mycode` 逐分支收敛设计树；
2. 满足"每个决策分支有结论"后定稿；
3. 以"离线可完整跑完一局 + 回放可重放"为验收。
```

## 模板的用途（对应已迁入的 skill）

- `grill-mycode`：评审达成共识后，在对应 ADR 追加「评审记录」章节（❓ 问题 / 💬 讨论 / ✅ 共识）；无对应 ADR 时按本编号规则新建。
- `closeout`：会话结束时，把"难回退 + 无上下文费解 + 真权衡"的决策提为 ADR 候选，写入编号 +1 的新 ADR。
- `improve-codebase-architecture` / `code-review`：读 `docs/adr/` 了解既有决策，不重议已被记录的决策。
