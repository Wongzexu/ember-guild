# ADR-002: 战斗结算语义与表现层回放契约（A 原教旨 + 事实序 FIFO）

> 日期：2026-09-04
> 状态：accepted
> 关联：DECISIONS.md「#3 过审 Q5 · 命中/闪避法案」（2026-08-29）、「攻击与击中特效分层映射」（2026-09-01）、「命中冲击 fx 的元素归属 = 攻击方」（2026-09-03）；PENDING #18（元素底座）/ #19（空间语义）；`game/src/engine/expedition.js`（stepExpeditions）、`game/src/ui/ExpeditionPanel.vue`（playbackQueues）

## 一、背景

引擎现状（M1~M2）：`stepExpeditions` 为纯函数 reducer，攻击在倒计时归零的**出手瞬间同步结算完毕**（命中 roll → 伤害 roll → 击杀连锁 gold/xp/掉落/spawn，rng 单流可复现）；combatEvents 只带单调 seq id，**无时间锚点**——burst 帧内多次攻击在时间上不可分辨。

表现层现状：`visuals.js` 为每单位存 `attackHitMs`（出手动画到命中落点的时序）；真战斗面板 `ExpeditionPanel.vue` 在收到事件的墙钟上本地加 `attackHitMs` 延迟播命中特效，而血条直接绑 `party.monster.hp` 实时状态——事实（血量已扣）与表现（命中特效未落地）已经错位，且 burst/回补帧会漂移、堆积。

辩论起源：若未来出现反应类技能（无敌盾），其激活时刻 `t_inv` 落在某刀的出手 `t` 与命中 `hitAt` 之间，"顶着盾掉血"是否穿帮？由此对三个候选模型做了完整推演：

| 模型 | 语义 | 判定 |
|------|------|------|
| **A 原教旨（snapshot）** | 出手瞬间 `t` 原子结算一切，hitAt 纯表现 | ✅ 采纳 |
| A'（模拟前摇） | 前摇时长进模拟参数，引擎在 `t+windup` 结算 | ❌ 备用升级路径 |
| 半锁定 | 数值在 `t` 锁定、状态在 `hitAt` 复查 | ❌ 否决 |

## 二、决策

### 2.1 结算语义 = A 原教旨（snapshot）

所有伤害、击杀、掉落、随机数消耗在攻击**出手瞬间（t）原子完成**；`visuals.js` 的 `attackHitMs` 仅为表现层延迟播放参数，不影响任何逻辑状态。反应类状态（无敌/闪避触发/打断）只对**激活之后出手**的攻击生效——出手即锁定。引擎不持有任何"在途攻击"状态，A 死后不影响 B 已结算的血，burst 回补天然安全。

否决理由存档：

- **A'**：迫使引擎引入在途攻击调度，并连带产生"出手者前摇中死亡，已 commit 攻击是否落地"的裁决链（弹道所有权/可打断吟唱语义），为尚不存在的技能系统付引擎重构费——对挂机 PVE 过设计。
- **半锁定**（t 锁数值 + hitAt 查状态）：实际是 A' 的隐含变体（hitAt 必须成为引擎时刻才能复查），且引入"每个新 buff 归类为影响数值还是影响状态"的**永久分类税**——分类标准是 UX 显著度而非机制属性，会持续漂移；状态最多、bug 面最大。

### 2.2 表现层契约：事实序 FIFO 反穿帮队列

引擎事件补三类锚点（不改变任何结算时序）：

1. **`t` 时间戳**：每条 combatEvent 附出手瞬间的模拟时间（以 `meta.totalPlayMs` 为基准的单调钟；引擎可精确计算：第 k 次开火时刻 = `T + 余量时钟 + dt`）——burst 内多击自此在时间上可分辨，一切回放的前提；
2. **`spawn` 事件**：burst 击杀后引擎已刷新新怪，表现层需要该事件在死亡动画结束后换模（当前 spawn 静默、换图超前于动画）；
3. **`element`/攻击类型字段**：随 PENDING #18 元素底座落地（字段先留位），fx 选色（2026-09-03 决策）的事件侧落点。

表现层统一规则——**每单位一条按事实提交顺序（t）排列的 FIFO 播放队列**（收编 `ExpeditionPanel` 现有 `playbackQueues` 与游离的 `scheduleImpact` 定时器路径）：

```
同一目标身上，按 t 排序依次处理：
- 伤害事实（t < t_inv）→ 掉血飘字 + 受击
- buff 激活（t_inv，如无敌盾）→ 排在所有 t < t_inv 的伤害事实之后播放
- 格挡事实（t > t_inv）→ 排在 buff 之后，显示"叮"（无伤害，晚播无害）
每条播放时刻 = max(自身 hitAt, 队列前项播完)
```

三性质：**事实顺序 = 显示顺序（永不穿帮）**；盾的显示延迟上限 = 一个前摇（当前 ~700ms）；玩家叙事 = "先挨一刀、再开盾保后续"，符合挂机 PVE 直觉。

配套两条：

- **血条/飘字改绑事件流**：display HP = 同步点 HP − 已到 hitAt 的伤害和；出征开始/暂停/backlog 超阈值（建议 3s）时整队清空、直接对齐 live state（快进模式）——否则离线回补会把队列堆爆。
- **events 属纯表现数据，可截断**（rng/数值不可）：引擎可为单 tick 事件数设上限。

### 2.3 表现层红线

**表现层不得改写事实**——只能排序、延迟、截断（均不改变任何事实的成立与否）；禁止为视觉圆谎而取消/捏造事实的显示语义。facts（引擎）与 pacing（表现）的所有权以此划界。

## 三、后果

### 正面影响
- 引擎零在途状态，rng 次序契约（#12 Q4）不受任何表现时序污染，burst/离线回补天然确定；
- 事件契约（t/spawn/element）对 snapshot 与未来任何语义前向兼容——语义升级不改契约；
- "盾亮了还掉血"类穿帮被时序消化而非谎言消化，玩家叙事自洽。

### 代价与风险
- 反应类技能**没有反应窗口**（无敌挡不住已出手的刀）——对挂机自动战斗无感，若未来设计上需要反应窗口，走 A' 升级（见排除事项）；
- 血条等表现需从"绑 live state"改为"事件流重放 + 快进对齐"——`ExpeditionPanel` 现有绑法需重构，越晚改越贵；
- buff 特效显示晚于其逻辑生效时刻最多一个前摇（~700ms）——可接受，不构成误判。

## 四、排除事项

- **不采用半锁定语义**（数值/状态双轨）——分类税永久化，否决不复提；
- **不现在实施 A'**（模拟前摇/在途攻击调度）——仅当"反应窗口"成为明确设计需求时重启，届时须连带裁定"出手者前摇中死亡，已 commit 攻击是否落地"（弹道所有权）；
- **不做弹道/投射物子系统**——若未来出现需要延迟判定的技能，单独立项，不污染通用近战/指向性技能的结算内核；
- **表现层不持有任何结算权威**——不因视觉需要修改事实的成立与否（红线见 §2.3）。

## 五、实施与验证

1. 引擎侧（小改）：`stepExpeditions` 的 `emitCombatEvent` 附 `t`（开火时刻精确值）；击杀后补发 `spawn` 事件（带 visual/name）；`element` 字段留位待 #18；
2. 表现侧：`ExpeditionPanel` 收编 `scheduleImpact` 入 `playbackQueues`，血条改事件流重放 + backlog 快进对齐；
3. 验证：vitest 补 t 单调性与 burst 帧时间戳用例；M2 战斗面板以"连杀不穿帮、回补不堆爆"手玩验收；
4. 本 ADR 不阻塞 M2 装备系统其他工作，战斗面板开工前完成 §五 1~2。
